# План, проверки и pull request: catalog

Обязательные правила находятся в [AGENTS.md](../AGENTS.md). Сначала обсуждаем проблему и план и получаем явное согласие, затем реализуем задачу в отдельной ветке. Продолжение задачи остаётся в существующей ветке/PR.

## Проверки до публикации

npm run typecheck и npm run build:local; при изменении HTTP-контракта или связи с shell — соответствующие проверки integration.

Команды сверять с актуальным package.json и конфигурацией CI. Непроведённые проверки не считать успешными. При изменении поведения обновлять относящиеся к задаче docs/ и README; при отсутствии таких изменений объяснить это в PR. Для Markdown достаточно проверки ссылок, содержания, UTF-8 и git diff --check.

## GitHub CLI

Навык github-pr установлен локально в ~/.codex/skills/github-pr/SKILL.md, не входит в этот Git-репозиторий и не требуется для запуска приложения. На другой машине доступны те же команды Git и gh; навык не устанавливается автоматически. GitHub CLI — отдельное приложение, не npm-зависимость.

1. До push проверить gh auth status, remote, целевую ветку и существующий PR задачи.
2. Просмотреть diff и закоммитить только проверенные изменения задачи. Существующие незавершённые правки не включать автоматически.
3. Подготовить временный UTF-8 Markdown body-файл с описанием проблемы и результата, изменений, документации, проверок и ограничений. Файл не включать в commit.
4. Отправить ветку через git push. Создать PR через gh pr create с явными --repo, --base, --head, --title и --body-file. Если PR уже существует, обновить его через gh pr edit.
5. Проверить gh pr view и gh pr checks, вернуть реальную ссылку на PR и статус CI. Pending не означает успех. Merge и удаление ветки требуют отдельного указания.

Если remote или доступ отсутствует, сохранить описание и сообщить блокер до push. Ветка на GitHub и форма compare не являются созданным PR.
