# Правила catalog-репозитория

Это отдельный репозиторий команды каталога. Команда не зависит от shell и не должна импортировать его код.

## Обязательный процесс задачи

1. До изменений прочитать [архитектуру проекта](docs/architecture.md) и README. Проверить Git-статус, текущую ветку, remote и целевую ветку PR.
2. Для новой задачи с изменениями создать отдельную ветку от актуальной целевой ветки; продолжать существующую задачу в её ветке. Не работать напрямую в main. Незавершённые чужие изменения не сбрасывать и не включать в свой commit; при необходимости использовать отдельный worktree.
3. Перед реализацией кратко описать цель, границы и ожидаемый результат в сообщении задачи. Итоговое описание задачи и выполненной работы хранить в PR. Файлы docs/tasks не создавать.
4. Выполнять изменения по FSD, соблюдая границы микрофронтенда и публичные контракты.
5. После каждой задачи проверить актуальность docs/architecture.md, README и затронутых документов. Обновить описание структуры, ответственности, зависимостей, контрактов и конфигурации в той же ветке. Документация описывает текущее устройство проекта; историю выполнения хранить в Git и PR. Если документация не требует изменений, объяснить причину в PR.
6. Выполнить npm run typecheck и npm run build:local для изменений кода; выполнить относящиеся к задаче тесты и интеграционные проверки при изменении контрактов. Для изменений только Markdown проверить ссылки, соответствие коду, кодировку и git diff --check; сборка не обязательна. Не объявлять непроведённые проверки успешными.
7. Просмотреть итоговый diff, сделать commit только изменений задачи, push ветки в remote и создать PR по шаблону .github/pull_request_template.md. Описать проблему, результат, проверки и документацию. Push ветки и создание PR входят в стандартное завершение задачи; автоматический merge не входит.
8. Проверить результаты CI, устранить относящиеся к задаче ошибки и дать ссылку на PR. При отсутствии доступа к remote, инструментов или при незавершённых проверках явно сообщить блокер; не называть публикацию завершённой.
9. Для задачи в нескольких репозиториях использовать отдельные ветки и PR, связать PR ссылками и описать порядок совместимого выпуска.

## Обязательная архитектура FSD

- Каждый микрофронтенд, включая shell, развивается по Feature-Sliced Design. Правила и распределение ответственности описаны в [архитектуре](docs/architecture.md#fsd).
- Новые модули размещать по слоям и предметным слайсам; зависимости направлять только вниз. Между слайсами использовать публичный API, не импортировать внутренние файлы другого слайса.
- Создавать только необходимые слои и сегменты. Не складывать бизнес-логику в shared и не импортировать исходники соседних репозиториев.
- Существующая плоская структура ещё не является FSD. При изменении legacy-кода переносить затронутую ответственность в подходящий слой в пределах задачи; крупный перенос оформлять отдельной задачей. Не объявлять миграцию завершённой без проверки структуры и импортов.


## Границы

- Catalog запускается standalone на `http://localhost:5174`.
- Catalog отдает `remoteEntry.js` для shell.
- Публичный модуль: `catalog/CatalogApp`.
- Контракт с shell - это exposed module, URL remote и договоренная форма интеграции.

## Команды

- `npm install` - установить зависимости catalog.
- `npm run dev` - запустить standalone/dev remote на `http://localhost:5174`.
- `npm run dev:remote` - то же самое, явное имя для запуска из shell.
- `npm run typecheck` - проверить TypeScript.
- `npm run build` - собрать catalog.

## Shared UI

Для независимого checkout `@microfronts/ui` поставляется готовым tarball в `vendor/`. Архив и package-lock.json должны храниться в Git. После обновления пакета обновлять версию и lock-файл. Пакет platform удалён из зависимостей: контракт описан в `src/remote-props.ts`, связь через props/callbacks. Репозитории не импортируют исходники друг друга.

Production build требует HTTPS-переменные из `.env.example`. Для локальной проверки сборки используется `npm run build:local`; общий стенд и E2E находятся в отдельном `integration`-репозитории.
